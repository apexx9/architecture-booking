# UI State Design
Identify only states relevant to the real feature contract: loading, populated, empty, validation error, request/system error, success, disabled/unavailable and partial data. Define the visual treatment and concise copy. Do not invent business rules, retry policy, permissions or API response shapes. If the contract is unknown, expose the UI boundary and ask Aaron.
